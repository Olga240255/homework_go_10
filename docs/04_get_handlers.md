# 04. GET handler-функции

## 04.1 Получить список из store

**Что тренируем.** Разделение обязанностей handler и хранилища.

**Как рассуждать.** `ListNotes` не должен сам обходить map — у него нет доступа к внутренним полям Store. Получите готовый срез через `h.store.List()`.

**Мини-пример.** Handler знает HTTP, Store знает хранение; между ними передаётся `[]note.Note`.

**Частая ошибка.** Перенести map в пакет httpapi и смешать HTTP с данными.

**Как проверить.** Сначала `make test-store`, затем переходите к 04.2.

## 04.2 Ответ GET /notes

**Что тренируем.** `200 OK` и JSON-массив.

**Как рассуждать.** Передайте срез в `writeJSON` со status `http.StatusOK`. Даже пустой список должен быть успешным ответом, потому что запрос корректен.

**Мини-пример.** Пустое хранилище возвращает `200` и `[]`, а не `404`.

**Частая ошибка.** Считать отсутствие элементов ошибкой ресурса: сам endpoint списка существует.

**Как проверить.** `go test ./internal/httpapi -run TestGetEmptyList`.

## 04.3 ID из path

**Что тренируем.** `r.PathValue("id")` и `strconv.Atoi`.

**Как рассуждать.** В `GetNote` вызовите общий `parseID`. В нём прочитайте именованный сегмент, преобразуйте в int и разрешите только положительные значения.

**Мини-пример.** `/notes/15` → строка `"15"` → int 15.

**Частая ошибка.** Игнорировать ошибку Atoi: `abc` превратится в zero value и будет выглядеть как ID 0.

**Как проверить.** После 07.4: `go test ./internal/httpapi -run TestInvalidID`.

## 04.4 Отличить 400 от 404

**Что тренируем.** Выбор статуса по причине ошибки.

**Как рассуждать.** `abc` — неправильный формат запроса, поэтому 400. `999` — корректное число, но Store вернул `ErrNotFound`, поэтому 404. Используйте `errors.Is`, а не сравнение текста ошибки.

**Мини-пример.** `/notes/abc` и `/notes/999` должны дать разные status.

**Частая ошибка.** Возвращать 404 для любой ошибки ID и скрывать ошибку формата.

**Как проверить.** `go test ./internal/httpapi -run 'TestInvalidID|TestGetExistingAndUnknown'`.

## 04.5 Успешный ответ одной заметки

**Что тренируем.** Завершение ветки успеха после ранних return.

**Как рассуждать.** После успешного parseID и Store.Get верните Note через `writeJSON` со status 200. Ветви 400/404 должны завершаться `return`, чтобы не записать второй ответ.

**Мини-пример.** Существующий ID 1 возвращает `{"id":1,"title":"...","text":"..."}`.

**Частая ошибка.** После `writeError` продолжить выполнение и дописать успешный JSON в тот же body.

**Как проверить.** `go test ./internal/httpapi -run TestGetExistingAndUnknown`.
