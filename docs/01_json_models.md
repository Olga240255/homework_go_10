# 01. JSON и модели

## 01.1 JSON-теги модели Note

**Что тренируем.** Связь экспортируемых полей Go и имён полей JSON.

**Как рассуждать.** Клиент не знает Go-имён `ID`, `Title`, `Text`. В договоре API мы выбрали `id`, `title`, `text`, поэтому эти внешние имена нужно зафиксировать в тегах структуры. Поля остаются экспортируемыми, иначе `encoding/json` их не увидит.

**Мини-пример.** `Note{ID: 1}` должен превратиться в `{"id":1,...}`, а не в `{"ID":1,...}`.

**Частая ошибка.** Написать тег после неэкспортируемого поля `title string`: тег не делает поле экспортируемым.

**Как проверить.** `go test ./internal/note -run TestNoteJSONTags`.

## 01.2 JSON для создания заметки

**Что тренируем.** Отдельная Go-структура для body запроса `POST /notes`.

**Как рассуждать.** При создании клиент присылает только `title` и `text`; ID назначает сервер. Добавьте теги в `createNoteRequest` и не добавляйте туда ID. Это маленький входной договор handler, а не копия всей модели.

**Мини-пример.** `{"title":"HTTP","text":"request"}` заполняет два поля входной структуры.

**Частая ошибка.** Принимать ID клиента и сохранять его: тогда два клиента могут выбрать один ID.

**Как проверить.** После раздела 05 тест `TestPostValid` должен декодировать body и вернуть ID 1.

## 01.3 JSON для частичного изменения

**Что тренируем.** Указатели в body `PATCH /notes/{id}`.

**Как рассуждать.** Для PATCH нужно отличать «поле не прислали» от «поле прислали пустым». Поэтому `Title` и `Text` остаются указателями. Добавьте JSON-теги, сохранив типы `*string`.

**Мини-пример.** После `{"text":"new"}` поле `Text` не nil, а `Title` nil — title менять нельзя.

**Частая ошибка.** Использовать обычные строки: их zero value одинаков для пропущенного поля и явного `"title":""`.

**Как проверить.** После раздела 06 запустите `go test ./internal/httpapi -run TestPatch`.

## 01.4 Почему Changes тоже использует указатели

**Что тренируем.** Передачу смысла «поле было в запросе» из HTTP-слоя в store.

**Как рассуждать.** Handler декодирует JSON, но решение об изменении данных принимает store. Если по дороге заменить указатели обычными строками, информация о присутствии поля потеряется. Допишите учебный комментарий над `Changes` своими словами.

**Мини-пример.** `Changes{Text: &newText}` меняет только текст; `Title: nil` сохраняет старый заголовок.

**Частая ошибка.** Создавать `Changes{Title: new(string)}` при отсутствии title: это уже не nil и похоже на попытку стереть заголовок.

**Как проверить.** `go test ./internal/note -run TestStorePatchAndDelete` после реализации store.

## 01.5 Поле, которое нельзя отдавать клиенту

**Что тренируем.** Тег `json:"-"`.

**Как рассуждать.** `PublicExample.Secret` существует внутри Go-программы, но не является частью API. Добавьте `json:"-"`; для `Title` задайте имя `title`. Этот маленький тип отделён от Note, чтобы не усложнять основной договор API.

**Мини-пример.** `PublicExample{Title:"A", Secret:"token"}` должен дать `{"title":"A"}`.

**Частая ошибка.** Надеяться, что слово `Secret` автоматически скроет поле: экспортируемые поля кодируются, пока тег не говорит обратное.

**Как проверить.** `go test ./internal/note -run TestJSONDash`.
