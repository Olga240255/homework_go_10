# 05. POST /notes

## 05.1 Decoder читает r.Body

**Что тренируем.** Потоковое чтение JSON из HTTP-запроса.

**Как рассуждать.** `r.Body` реализует `io.Reader`, поэтому его можно передать в `json.NewDecoder`. В `decodeJSON` вызовите `Decode(dst)` и верните ошибку вызывающему handler.

**Мини-пример.** JSON `{"title":"HTTP","text":"body"}` заполняет `createNoteRequest`.

**Частая ошибка.** Игнорировать ошибку Decode и сохранить структуру с zero values.

**Как проверить.** После 05.4: `go test ./internal/httpapi -run TestPostValid`.

## 05.2 Неизвестные поля как опечатка

**Что тренируем.** `Decoder.DisallowUnknownFields`.

**Как рассуждать.** Включите проверку до Decode. Тогда `titel` не будет молча отброшено; клиент получит 400 и увидит ошибку раньше.

**Мини-пример.** `{"titel":"HTTP"}` не соответствует входной структуре с полем `title`.

**Частая ошибка.** Вызвать `DisallowUnknownFields` после Decode: текущий JSON уже прочитан.

**Как проверить.** `go test ./internal/httpapi -run TestPostErrors/unknown_field` после реализации POST.

## 05.3 Ровно один JSON-объект

**Что тренируем.** Проверку конца потока после первого Decode.

**Как рассуждать.** После успешного Decode попробуйте прочитать ещё одно значение. Ожидается `io.EOF`. Если прочитан второй объект или возникла другая ошибка, весь body некорректен.

**Мини-пример.** `{"title":"a"}{"title":"b"}` нельзя принимать только наполовину.

**Частая ошибка.** Считать первый успешный Decode доказательством корректности всего body.

**Как проверить.** Добавьте локальный тест по примеру classroom и запустите `make test-http`.

## 05.4 Центральный путь CreateNote

**Что тренируем.** Цепочку JSON → Go struct → Store.

**Как рассуждать.** Создайте `createNoteRequest`, вызовите `decodeJSON`, при ошибке верните 400 и `return`. Затем передайте title и text в Store.Create. `ErrEmptyTitle` тоже означает 400.

**Мини-пример.** Корректный body доходит до Store ровно один раз; сломанный body не меняет данные.

**Частая ошибка.** Вызывать Store.Create даже после ошибки Decode.

**Как проверить.** `go test ./internal/httpapi -run 'TestPostValid|TestPostErrors'`.

## 05.5 Ответ 201 и Location

**Что тренируем.** Семантику успешного создания.

**Как рассуждать.** После Create поставьте `Location: /notes/{id}` до записи ответа. Затем верните созданную Note через `writeJSON` со status `http.StatusCreated`.

**Мини-пример.** Первая заметка даёт `201 Created`, `Location: /notes/1` и JSON с ID 1.

**Частая ошибка.** Вернуть 200 просто потому, что запрос завершился без ошибки: 201 точнее сообщает, что создан новый объект.

**Как проверить.** `go test ./internal/httpapi -run TestPostValid`.
