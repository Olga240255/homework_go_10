# 02. Хранилище в памяти

## 02.1 Список как [] вместо null

**Что тренируем.** Безопасное чтение map и предсказуемый JSON-массив.

**Как рассуждать.** Возьмите `RLock`, создайте непустой по типу срез через `make([]Note, 0, len(s.notes))`, скопируйте значения и отсортируйте по ID. Пустой созданный срез кодируется как `[]`, а nil-срез — как `null` в классическом `encoding/json`.

**Мини-пример.** IDs 3 и 1 в map должны вернуться как `[1, 3]`.

**Частая ошибка.** Полагаться на порядок обхода map: Go его не гарантирует.

**Как проверить.** `go test ./internal/note -run TestStoreEmptyList`.

## 02.2 Поиск одной заметки

**Что тренируем.** Паттерн `value, ok := map[key]` и доменную ошибку.

**Как рассуждать.** Под `RLock` прочитайте значение. Если ключа нет, верните `Note{}` и `ErrNotFound`; handler позже превратит эту ошибку в `404`.

**Мини-пример.** В пустом store `Get(1)` не является ошибкой сервера — это ожидаемое отсутствие объекта.

**Частая ошибка.** Вернуть только zero value без ошибки: handler не сможет отличить отсутствующую заметку от настоящей пустой.

**Как проверить.** `go test ./internal/note -run TestStoreCreateAndGet` после задачи 02.3.

## 02.3 Создание и серверный ID

**Что тренируем.** Проверку данных, запись под mutex и назначение ID.

**Как рассуждать.** Сначала примените `strings.TrimSpace` к title и отклоните пустой результат. Затем под `Lock` создайте Note с `nextID`, сохраните её и увеличьте счётчик. Текст может быть пустым — такого запрета в договоре нет.

**Мини-пример.** Первый успешный POST создаёт ID 1, второй — ID 2.

**Частая ошибка.** Увеличить `nextID` до проверки title: невалидный запрос оставит необъяснимый пропуск ID.

**Как проверить.** `go test ./internal/note -run 'TestStoreCreateAndGet|TestStoreRejectsEmptyTitle'`.

## 02.4 Частичное изменение

**Что тренируем.** PATCH-семантику на уровне данных.

**Как рассуждать.** Сначала отклоните `Changes{}` как `ErrNoChanges`. Под `Lock` найдите заметку. Меняйте каждое поле только при ненулевом указателе; новый title снова проверьте после `TrimSpace`. Сохраните изменённую копию обратно в map.

**Мини-пример.** `Changes{Text:&newText}` не должен менять title.

**Частая ошибка.** Всегда присваивать `item.Title = *changes.Title`: при nil программа получит panic.

**Как проверить.** `go test ./internal/note -run TestStorePatchAndDelete`.

## 02.5 Удаление и mutex

**Что тренируем.** Проверяемое удаление из общей map.

**Как рассуждать.** Возьмите `Lock`, проверьте существование ID, затем вызовите `delete`. Если объекта нет, верните `ErrNotFound`: HTTP-слой выберет `404`.

**Мини-пример.** Первое `Delete(1)` успешно, повторное должно вернуть `ErrNotFound`.

**Частая ошибка.** Считать, что `delete` сам сообщает об отсутствии ключа: он молча ничего не делает.

**Как проверить.** `make test-store`, затем `go test -race ./internal/note`.
