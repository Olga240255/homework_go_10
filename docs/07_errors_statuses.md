# 07. Ошибки, headers и status

## 07.1 Headers идут первыми

**Что тренируем.** Порядок формирования HTTP response.

**Как рассуждать.** Прочитайте готовую `writeJSON` и допишите комментарий своими словами: `Header().Set` вызывается до `WriteHeader`, иначе заголовок может не попасть в уже начатый ответ.

**Мини-пример.** Сначала `Content-Type`, затем `201`, затем JSON.

**Частая ошибка.** Установить Content-Type после Encode.

**Как проверить.** В тесте проверьте `response.Header().Get("Content-Type")`.

## 07.2 Content-Type у JSON

**Что тренируем.** Явное описание формата body.

**Как рассуждать.** Все успешные JSON-ответы и JSON-ошибки должны пройти через `writeJSON`/`writeError`. Ответ 204 — исключение: body отсутствует, поэтому JSON Content-Type не требуется.

**Мини-пример.** `GET /notes` → `application/json; charset=utf-8`.

**Частая ошибка.** Ставить Content-Type только для POST, забывая GET и ошибки.

**Как проверить.** Добавьте assertion по образцу classroom и запустите `make test-http`.

## 07.3 Status важнее поля error

**Что тренируем.** Правильный HTTP-контракт ошибки.

**Как рассуждать.** `writeError` должен получить настоящий status 400 или 404. JSON `{"error":"..."}` объясняет причину человеку, но клиент сначала принимает решение по status.

**Мини-пример.** Отсутствующая заметка — `404` + JSON, а не `200` + JSON.

**Частая ошибка.** Вызвать только `w.Write` и не заметить неявный 200.

**Как проверить.** `go test ./internal/httpapi -run TestGetExistingAndUnknown`.

## 07.4 Положительный целый ID

**Что тренируем.** Границу между форматом запроса и поиском данных.

**Как рассуждать.** Реализуйте `parseID`: прочитайте `r.PathValue("id")`, вызовите `strconv.Atoi`, отклоните ошибку, ноль и отрицательное число статусом 400. Возвращайте `(0, false)`, чтобы handler завершился.

**Мини-пример.** `abc`, `0`, `-3` — 400; `999` проходит парсинг и может стать 404 позже.

**Частая ошибка.** Вернуть 404 ещё до Atoi: тогда неверный формат выглядит как корректный отсутствующий объект.

**Как проверить.** `go test ./internal/httpapi -run TestInvalidID`.

## 07.5 Не писать после 204

**Что тренируем.** Завершение ответа без данных.

**Как рассуждать.** Проверьте `DeleteNote`: после `WriteHeader(204)` функция должна закончиться. Уберите Encode, Write и лишний `writeJSON`.

**Мини-пример.** `response.Body.Len()` равен 0.

**Частая ошибка.** Считать перевод строки от Encoder «не настоящим body»: это всё равно байты ответа.

**Как проверить.** `go test ./internal/httpapi -run TestDelete`.
