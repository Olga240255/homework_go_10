# 06. PATCH и DELETE

## 06.1 Прочитать ID и PATCH body

**Что тренируем.** Одновременную работу path parameter и JSON body.

**Как рассуждать.** Сначала получите ID через `parseID`; при ошибке сразу завершите handler. Затем декодируйте `patchNoteRequest`. Это два разных источника: path выбирает объект, body описывает изменения.

**Мини-пример.** `PATCH /notes/1` + `{"text":"ready"}`.

**Частая ошибка.** Пытаться получить ID из body или title из path.

**Как проверить.** `go test ./internal/httpapi -run TestPatch` после задач 06.2–06.3.

## 06.2 Передать изменения в Store

**Что тренируем.** Сохранение nil-значений между слоями.

**Как рассуждать.** Создайте `note.Changes{Title: input.Title, Text: input.Text}` без разыменования. Store сам решит, какие поля присутствовали и что проверять.

**Мини-пример.** При `Text != nil` и `Title == nil` старый title остаётся.

**Частая ошибка.** Сконструировать новую Note только из body: пропущенные поля обнулятся.

**Как проверить.** `go test ./internal/note -run TestStorePatchAndDelete`.

## 06.3 Статусы PATCH

**Что тренируем.** Сопоставление доменных ошибок и HTTP.

**Как рассуждать.** `ErrNotFound` превращается в 404. `ErrEmptyTitle` и `ErrNoChanges` — в 400. При успехе верните 200 и обновлённую заметку. Удобно использовать switch с `errors.Is`.

**Мини-пример.** Пустой `{}` — 400; `/notes/999` — 404; корректное изменение — 200.

**Частая ошибка.** Любую ошибку Store превращать в 500, хотя причины ожидаемы.

**Как проверить.** `go test ./internal/httpapi -run TestPatch`, затем добавьте тест пустого PATCH.

## 06.4 DELETE и отсутствующий объект

**Что тренируем.** Удаление выбранного path-объекта.

**Как рассуждать.** Получите ID, вызовите Store.Delete. При `ErrNotFound` верните 404 и завершите функцию.

**Мини-пример.** Повторный DELETE того же ID возвращает 404.

**Частая ошибка.** Всегда возвращать 204, даже если ничего не было удалено: клиент теряет важную информацию.

**Как проверить.** `go test ./internal/httpapi -run TestDelete` и добавьте проверку повторного DELETE.

## 06.5 Пустой ответ 204

**Что тренируем.** Status без body.

**Как рассуждать.** После успешного удаления вызовите только `w.WriteHeader(http.StatusNoContent)`. Не вызывайте `writeJSON`, потому что Encoder добавит данные и перевод строки.

**Мини-пример.** Ответ содержит строку `HTTP/1.1 204 No Content`, затем сразу заканчивается.

**Частая ошибка.** Вернуть `204` и `{}`: название статуса прямо обещает отсутствие содержимого.

**Как проверить.** `go test ./internal/httpapi -run TestDelete`.
