# 08. HTTP-тесты и ручная проверка

## 08.1 Тест сломанного JSON

**Что тренируем.** `httptest.NewRequest` и `httptest.NewRecorder` для ошибки клиента.

**Как рассуждать.** Уберите `t.Skip` в `TestStudentPostInvalidJSON`. Создайте router, POST-запрос с body `{"title":`, recorder и вызовите `ServeHTTP`. Проверьте status 400.

**Мини-пример.** Настоящий порт и запущенный сервер не нужны.

**Частая ошибка.** Вызывать CreateNote напрямую: тогда не проверяется выбор маршрута.

**Как проверить.** `go test ./internal/httpapi -run TestStudentPostInvalidJSON`.

## 08.2 Тест отсутствующей заметки

**Что тренируем.** Разницу между 404 и 400.

**Как рассуждать.** Создайте GET `/notes/999`. ID корректен, но store пуст, значит ожидается 404. Дополнительно убедитесь, что body содержит поле error.

**Мини-пример.** Для `/notes/abc` ожидается уже 400 — это другой тест.

**Частая ошибка.** Проверить только body и забыть status.

**Как проверить.** `go test ./internal/httpapi -run TestStudentGetUnknown`.

## 08.3 Тест частичного PATCH

**Что тренируем.** Подготовку состояния и проверку неизменившегося поля.

**Как рассуждать.** Создайте Note через Store, отправьте PATCH только с `text`. Декодируйте ответ и проверьте одновременно новый Text и прежний Title.

**Мини-пример.** `{"text":"ready"}` не должен стирать title.

**Частая ошибка.** Проверить только status 200 и не заметить потерю данных.

**Как проверить.** `go test ./internal/httpapi -run TestStudentPatch`.

## 08.4 DELETE не содержит body

**Что тренируем.** Полную проверку 204.

**Как рассуждать.** Создайте заметку, отправьте DELETE и проверьте две вещи: `response.Code == 204` и `response.Body.Len() == 0`.

**Мини-пример.** Даже `{}` или один перевод строки должны провалить тест.

**Частая ошибка.** Сравнивать TrimSpace(body) с пустой строкой: тест может скрыть лишний перевод строки.

**Как проверить.** `go test ./internal/httpapi -run TestStudentDeleteNoBody`.

## 08.5 Полный цикл и ручной запрос

**Что тренируем.** Связь отдельных endpoint в один пользовательский сценарий.

**Как рассуждать.** В одном тесте пройдите POST → GET → PATCH → DELETE → GET. Сохраняйте ID из ответа POST, не подставляйте его случайно. После зелёного теста запустите сервер и повторите `docs/manual-check.md` через curl или Insomnia.

**Мини-пример.** Последний GET удалённого ID должен вернуть 404.

**Частая ошибка.** Перезапустить router со свежим Store между запросами: полный цикл должен работать с одним состоянием.

**Как проверить.** `go test ./internal/httpapi -run TestStudentLifecycle`, затем `make ci`.
