# Домашняя работа — Notes API на Go

Домашняя работа повторяет путь classroom на другой предметной области. На занятии был Task API, здесь нужно самостоятельно собрать Notes API без новых библиотек и архитектурных слоёв.

Читайте задания по порядку в `docs/task.md`. После каждой задачи запускайте указанную короткую проверку. Не меняйте готовые проверочные тесты: они описывают договор API.

## Что нужно реализовать

| Endpoint | Успех | Ошибки |
|---|---:|---:|
| `GET /health` | `200` | — |
| `GET /notes` | `200` | — |
| `GET /notes/{id}` | `200` | `400`, `404` |
| `POST /notes` | `201` | `400` |
| `PATCH /notes/{id}` | `200` | `400`, `404` |
| `DELETE /notes/{id}` | `204` | `400`, `404` |

Модель:

```go
type Note struct {
    ID    int    `json:"id"`
    Title string `json:"title"`
    Text  string `json:"text"`
}
```

Запустите сервер:

```bash

```

Выполните запросы во втором терминале или повторите их в Insomnia по образцу classroom.

| Запрос | Ожидаемый status |
|---|---:|
| `POST /notes` | `201 Created` |
| `GET /notes` | `200 OK` |
| `GET /notes/1` | `200 OK` |
| `GET /notes/999` | `404 Not Found` |
| `GET /notes/abc` | `400 Bad Request` |
| `PATCH /notes/1` | `200 OK` |
| `DELETE /notes/1` | `204 No Content` |

Полные команды находятся в `docs/manual-check.md`.

## Правила HTTP-семантики

- `POST` возвращает `201`, потому что создан новый объект.
- Сломанный JSON и пустой `title` возвращают `400`: запрос клиента некорректен.
- Корректный, но отсутствующий ID возвращает `404`.
- `DELETE` при успехе возвращает `204` и пустой body.
- Для JSON-ответов нужен `Content-Type: application/json; charset=utf-8`.
- Порядок ответа: headers → `WriteHeader` → body.
